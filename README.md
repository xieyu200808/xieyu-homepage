# 谢宇 · 自我介绍（Vibe AI Lab）

线上地址：**https://xieyu200808.github.io/xieyu-homepage/**

一份单文件（HTML + CSS + JS）的自我介绍网页，作者谢宇，杭州电子科技大学 Vibe AI Lab 成员。
风格为「现代二次元唯美 + 玻璃拟态」，配色全部从下面四张角色图里取样。

## 本地运行

直接双击 `index.html` 即可，不需要装任何环境，也不需要起服务器。

## 页面结构

首页（名字打字机 + 常驻的 AI 聊天面板）→ AI 助手（人格来源 / 语气切换 / 开场白 / 技术信息）→ 关于我（我是谁、我在实验室想做什么）
→ 兴趣（哈迷 / 英文电影 / 3A 大作 / AI 工作流）→ 进了实验室之后最想先做的三件事 → 角色与配色来源 → 页脚。

聊天面板是常驻在首屏右侧的（窄屏会挪到标题下方），打开页面第一眼就能看到，不需要点右下角的小窗口。

## 两位角色（只作为配色出处）

页面主体是谢宇的自我介绍，这两位角色只是他的爱好，也是全部配色的出处，
所以页面上不展开她们的人物设定，只标注出自哪部作品：

- **椎名真昼（黄发）**：《关于邻家的天使大人不知不觉把我惯成了废人这档子事》——冰蓝、蜜金、藏青、酒红从她的两张图里取。
- **周防有希（黑发）**：《不时轻声地以俄语遮羞的邻座艾莉同学》——暖棕和蔷薇粉从她的两张图里取。

AI 助手的提示词里也只有一句话级别的区分（黄发/黑发、温柔/嘴硬），并且写死了一条硬规则：
**不把俄语安在周防有希身上**（俄语是同一部作品里艾莉莎的设定，助手不许混淆），
同时被问到角色时一句话说清出处就收住，不展开讲她们的设定。

这两位角色在页面上是**由模型扮演**的：真昼/有希各自以本人身份说话，开口先自我介绍，
再替谢宇把话讲清楚。助手**默认不把屏幕前的人当成谢宇**，介绍他一律用第三人称，
只有对方自报「我就是谢宇」才改口称呼本人。

## AI 助手

- 原理：对话真的在调小米 MiMo 开放平台 —— `POST https://api.xiaomimimo.com/v1/chat/completions`
  （OpenAI 兼容协议），模型 `mimo-v2.6-flash`，Key 写在 `index.html` 脚本顶部的 `MIMO_API_KEY` 常量里，
  不是本地假回复
- 人格：两位角色由模型**扮演**，各自以本人身份说话，开口先自我介绍（名字、出自哪部作品、
  在这个页面里负责什么），然后才回答访客的问题。点聊天面板左上角的头像切换：
  - 真昼模式（黄发头像）· 温柔治愈：蜜金 `#E8B96F`
  - 有希模式（黑发头像）· 嘴硬毒舌：蔷薇粉 `#C0888B`
- 立场：它们是替谢宇接待访客的。默认把屏幕前的人当成访客，介绍谢宇一律用第三人称；
  只有访客明说「我就是谢宇」才会改口称呼本人。早期版本把这条写反了——提示词让助手叫对方「小宇」，
  结果它对着陌生人也一口一个「你」，把主人的自我介绍说成了对方的自我介绍
- 提示词结构：公共事实 + 硬规则 + 身份语气 三层，切换身份只换最后一段。公共事实里同时写着两位角色的出处，
  所以身份必须在提示词的**开头和结尾各钉一次**（「你就是 X，不是 Y，全程不要自称 Y」），
  否则 flash 模型偶尔会把有希认成真昼——修之前 8 次里有 1 次，钉完之后 8/8 正确
- 位置：常驻首屏右侧（窄屏在标题下方）；右下角的胶囊按钮只在面板滚出视口后浮出来
- 交互：正在输入动画、30 秒超时保护、按错误码分级提示（400/401/402/403/421/429/5xx）、失败后一键重试
- 兜底：接口不可用时自动切到本地离线人格引擎，口吻也跟着当前模式走，页面不会冷场

### 省额度：这几处是专门为「别被人刷爆」做的

1. **关掉深度思考**：`mimo-v2.6-flash` 默认先跑一段推理再回答，连一句问候都会烧推理 token。
   页面里用 `thinking: { type: 'disabled' }` 关掉，实测 `reasoning_tokens` 归零、首字也更快。
   想要更深的推理，把 `MIMO_THINKING` 改成 `true`。
2. **不再「打开页面就发请求」**：早期版本把探活挂在 `window.load` 上，等于每个访客
   （以及每个会执行 JS 的搜索引擎爬虫）打开页面就白烧一次调用。现在改成第一次真要聊天时才探活，且全程只探一次。
3. **本机限流**：同一个浏览器两次提问至少间隔 2.5 秒（`MIN_SEND_GAP`），每天最多 40 次（`DAILY_SEND_LIMIT`），
   计数存在 localStorage。拦不住铁了心刷的人，但能挡住爬虫、路人和误触连点。
4. **修掉中文输入法误发**：选词时按回车曾经会把半截句子发出去，白多打一次接口，现在用
   `e.isComposing` 拦掉了。

### 关于 API Key

Key 写死在 `index.html` 顶部的 `MIMO_API_KEY` 常量里。页面是公开的、仓库也是公开的，
任何访问者都能在源码里看到它——**这也正是之前 DeepSeek 额度被人刷到欠费的真正原因**：
Key 一旦进了公开仓库，就会被扫密钥的机器人抓走，别人拿去跑自己的任务，账记在 Key 主人头上。
（当时 GitHub 的密钥保护还直接拦下了那次推送，说明这类 Key 正是扫描器盯着的目标。）

页面本身已经藏不住 Key 了，能做的是这四件事，按性价比排：

1. 在 MiMo 控制台给这个 Key **单独设额度上限**，别让它挂到主账号的全部余额；
2. 想更保险就换成 **Token Plan**（`tp-` 开头的 Key，套餐内定额调用，用完即停），
   公开的演示页很适合这种「用满即止」的计费方式；
3. 加一层**中转**（Cloudflare Worker / Vercel Function）代理请求，Key 只放服务端，
   再把页面里的 `MIMO_ENDPOINT` 换成中转地址；
4. 发现异常消耗就**去控制台吊销旧 Key、重建一个新的**，然后只改 `MIMO_API_KEY` 这一行。

注意：旧 Key 已经进过公开仓库的历史记录，把当前文件里那一行删掉并不能让它失效，必须去控制台吊销。

### 关于跨域

MiMo 接口返回的是 `access-control-allow-origin: *`，并且放行 `authorization`、`content-type`
请求头，所以不管是访问 GitHub Pages 上的地址，还是本地双击用 `file://` 打开，浏览器都能直接请求，
不需要中转。若某个浏览器仍然拦截了请求，页面会自动切到离线人格引擎，功能依然完整。

## 部署到 GitHub Pages

页面文件都在 `outputs/` 里，所以仓库就以这个目录为根目录——这样 `index.html` 直接躺在仓库根下，
GitHub Pages 打开就能跑，不用再配子目录。

```bash
cd outputs
git init
git add .
git commit -m "Vibe AI Lab homework"
git branch -M main
gh repo create <仓库名> --public --source=. --remote=origin --push   # 用 GitHub CLI 一步建仓并推送
```

不用 CLI 的话，手动建一个空仓库，然后：

```bash
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库的 Settings → Pages 里，把 Source 选为 `Deploy from a branch`，
Branch 选 `main` / `(root)`，保存后等一分钟，访问
`https://<用户名>.github.io/<仓库名>/` 即可。
