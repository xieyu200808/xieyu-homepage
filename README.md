# 谢宇 · 自我介绍（Vibe AI Lab）

一份单文件（HTML + CSS + JS）的自我介绍网页，作者谢宇，杭州电子科技大学 Vibe AI Lab 成员。
风格为「现代二次元唯美 + 玻璃拟态」，配色全部从下面四张角色图里取样。

## 文件结构

```
index.html          页面本体（样式、交互、AI 对话全部写在这一个文件里）
mahiru.jpg          椎名真昼（全屏氛围图 + 角色卡片一）
mahiru-2.jpg        椎名真昼 · 制服（角色卡片二）
yuki.jpg            周防有希 · 校园日常（角色卡片三）
yuki-q.png          周防有希 · Q 版全身立绘（角色卡片四，透明底，从原图重新抠的）
avatar-mahiru.jpg   从 mahiru-2.jpg 裁的方形头像（聊天面板用）
avatar-yuki.jpg     从 yuki.jpg 裁的方形头像（聊天面板用）
```

## 本地运行

直接双击 `index.html` 即可，不需要装任何环境，也不需要起服务器。

## 页面结构

首页（名字打字机 + 常驻的 AI 聊天面板）→ AI 助手（人格来源 / 语气切换 / 开场白 / 技术信息）→ 关于我（我是谁、我在实验室想做什么）
→ 兴趣（哈迷 / 英文电影 / 3A 大作 / AI 工作流）→ 进了实验室之后最想先做的三件事 → 角色与配色来源 → 页脚。

聊天面板是常驻在首屏右侧的（窄屏会挪到标题下方），打开页面第一眼就能看到，不需要点右下角的小窗口。

## 设计依据

页面的每一处颜色都能在原图里找到出处：

| 真昼（制服） | `#F0E0C0` `#1F1E34` `#844B55` `#EED9CD` | 深色底、酒红强调色、右侧蜜金暖光 |
| 有希（校园） | `#B49D81` `#715040` `#F4EEE8` `#4B6692` | 卡片描边与暖侧光里的那点暖棕，让配色不只剩冷调 |
| 有希（Q 版） | `#2C2528` `#928C90` `#C0888B` `#F9F4F1` | 「有希模式」下面板的描边、气泡边和柔光（蔷薇粉取自蝴蝶结） |

Q 版那张的取色过程：先用中位切分法把透明底 PNG 的不透明像素聚成 8 色
（`#FAF4F1` 14.0% / `#81757A` 13.9% / `#655D62` 13.8% / `#928C90` 13.5% / `#473F42` 11.7% /
`#251E20` 11.5% / `#DBCAC7` 10.9% / `#B19FA1` 10.8%），蝴蝶结再单独筛玫瑰色像素（s>0.15、v>0.55）平均得到 `#C0888B`。
这张素材是从原图重新抠的：只用"与边缘连通的白色"洪泛判背景，所以裙子上的白蕾丝没被抠掉；
只有紧贴背景的一圈做柔和过渡并反预乘，主体内部一律不透明；再只保留最大的那块前景，
甩掉原截图右上角残留的灰色 UI 条和孤立的星形装饰。全图 45225 种颜色，没有被量化。
卡面底色也跟着换成暖调的蔷薇灰：另外三张卡用的藏青底会把这张的深色发色压成一块脏灰。

排版依据：首屏文字左对齐、聊天面板放右侧；角色卡片用竖幅取景，标题压在画面下方，翻面看配色。

## 两位角色（只作为配色出处）

页面主体是谢宇的自我介绍，这两位角色只是他的爱好，也是全部配色的出处，
所以页面上不展开她们的人物设定，只标注出自哪部作品：

- **椎名真昼（黄发）**：《关于邻家的天使大人不知不觉把我惯成了废人这档子事》——冰蓝、蜜金、藏青、酒红从她的两张图里取。
- **周防有希（黑发）**：《不时轻声地以俄语遮羞的邻座艾莉同学》——暖棕和蔷薇粉从她的两张图里取。

AI 助手的提示词里也只有一句话级别的区分（黄发/黑发、温柔/嘴硬），并且写死了一条硬规则：
**不把俄语安在周防有希身上**（俄语是同一部作品里艾莉莎的设定，助手不许混淆），
同时被问到角色时一句话说清出处就收住，不展开讲她们的设定。

## AI 助手

- 原理：对话真的在调 DeepSeek API —— `POST https://api.deepseek.com/chat/completions`，模型 `deepseek-chat`，
  Key 写死在 `index.html` 脚本顶部的 `DEEPSEEK_API_KEY` 常量里（已做额度限制），不是本地假回复
- 人格：两套语气，点聊天面板左上角的头像切换
  - 真昼模式（黄发头像）· 温柔治愈：蜜金 `#E8B96F`
  - 有希模式（黑发头像）· 嘴硬毒舌：蔷薇粉 `#C28B90`
  - 两种模式共用同一份公共事实和硬规则，只替换语气那一段：不冒充这两位本人，被问到会大方承认
- 位置：常驻首屏右侧（窄屏在标题下方）；右下角的胶囊按钮只在面板滚出视口后浮出来
- 交互：正在输入动画、30 秒超时保护、HTTP 状态码分级提示、失败后一键重试
- 兜底：接口不可用时自动切到本地离线人格引擎，口吻也跟着当前模式走，页面不会冷场

### 关于 API Key

Key 写死在 `index.html` 顶部的 `DEEPSEEK_API_KEY` 常量里。部署到 GitHub Pages 后，
任何访问者都能在源码里看到这个 Key。这个 Key 已经做过额度限制，用于演示没有问题；
如果以后想长期公开，建议二选一：

1. 在 DeepSeek 控制台单独建一个只用于本项目的 Key，设置好额度上限，随时可以吊销；
2. 用一层中转（Cloudflare Worker / Vercel Function）代理请求，把 Key 放在服务端，
   再把页面里的 `DEEPSEEK_ENDPOINT` 换成中转地址。

### 关于跨域

从 `file://` 打开时，浏览器发出的请求会带上 `Origin: null`；DeepSeek 接口会把这个来源原样
写回 `access-control-allow-origin`，所以本地直接双击也能调用成功。若某个浏览器拦截了请求，
页面会自动切到离线人格引擎，功能依然完整。

## 部署到 GitHub Pages

页面文件都在 `outputs/` 里，所以仓库就以这个目录为根目录——这样 `index.html` 直接躺在仓库根下，
GitHub Pages 打开就能跑，不用再配子目录。

```bash
cd outputs
git init
git add .
git commit -m "Vibe AI Lab homework"
git branch -M main
gh repo create <仓库名> --public --source=. --remote=origin --push   # 用 GitHub CLI 一步建仓并推送
```

不用 CLI 的话，手动建一个空仓库，然后：

```bash
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库的 Settings → Pages 里，把 Source 选为 `Deploy from a branch`，
Branch 选 `main` / `(root)`，保存后等一分钟，访问
`https://<用户名>.github.io/<仓库名>/` 即可。
